# HolyPop 코드 검토 및 회귀 검증

2026-11-19 macOS에서 스타일·다중 모니터·영역 비율 변경 후 Rust 11개 테스트, JavaScript 2개 테스트, Rust 포맷 검사 및 Clippy 경고 검사를 통과했다. 실행 명령은 `cargo test --manifest-path src-tauri/Cargo.toml --locked`, `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `cargo clippy --manifest-path src-tauri/Cargo.toml --locked -- -D warnings`, `node --test ui/helpers.test.mjs`이며 모두 종료 코드 0이다. 실제 화면 검증 범위는 [TESTS.md](TESTS.md)에 기록한다.

검토 중 발견하여 반영한 사항:

- 활성 예약의 빈 요일 목록과 직접 선택한 구절의 번역 필터 불일치를 백엔드에서 거부한다.
- 저장과 읽기의 10MB 한도를 맞추고, 동시 저장을 직렬화한다. 새 스냅샷은 기존 파일을 덮어쓰지 않는다.
- 손상된 최신 설정은 보존한 채 이전 설정을 복구한다. 모든 설정이 손상되거나 폴더 읽기에 실패하면 경고를 반환한다.
- 오버레이 준비 전 요청은 창별로 보관하고 현재 세대의 요청만 표시한다. 표시 시작과 종료는 mutex와 세대 번호로 직렬화한다.
- 화면 입력 한도가 백엔드 검증과 일치한다. 사용자 입력은 `textContent`로 표시한다.
- 기존 설정에 `appearance`가 없으면 기본 스타일·색상·영역·모니터 값을 복원한다. 스타일은 허용 목록, 색상은 6자리 HEX, 영역은 10–100% 정수로 검증한다.
- 주 모니터·현재 설정 창의 모니터·전체·개별 선택을 처리하며 연결이 끊긴 대상은 주 모니터로 대체한다. 위치와 크기는 모니터의 물리 좌표를 그대로 전달하여 서로 다른 DPI에서 논리 좌표와 혼용하지 않는다.
- 동적 창 생성과 준비·종료 콜백을 작업 스레드에서 실행한다. Windows의 동기 명령 내 웹뷰 생성과 UI 스레드의 표시 mutex 대기로 인한 교착을 피한다.
- 늦게 준비된 창은 실제 표시를 시작할 때 종료 시한을 갱신한다. 이전 종료 타이머가 같은 세대의 새 시한보다 앞서면 연장된 시한까지 기다린다.
- 유리 스타일은 색조와 반투명 그라데이션으로 구현하며 화면 툴팁에 바탕화면 블러와의 차이를 설명한다. 창별 자원 정리는 숨김 이벤트에서 수행한다.

단위 테스트는 정상 시간대의 시작·종료 경계, 자정 및 일요일→월요일 경계, 하루 전체, 간격과 초기화, 비활성 예약, 시각·입력 검증, 날짜별 선택, 번역 필터, 한글·줄바꿈·따옴표의 저장 복원, 손상 복구와 저장 실패 시 기존 내용 보존, 이전 설정의 표시 기본값 복원, 잘못된 색상·영역·스타일 거부, 모니터 선택·연결 해제 시 대체 및 영역에 맞는 글자 크기 계산을 확인한다.

검토 범위에서 미해결된 중대한 코드 결함은 확인하지 못했다. 표시 세대·준비 지연·타이머 경합은 소스 검토했으며 실제 동시 실행을 단위 테스트로 재현하지 않았다. 실제 OS의 클릭 통과·포커스·Dock/작업 표시줄 복원·절전 복귀·다중 모니터 연결 변경과 혼합 DPI 및 Windows 실행 결과는 단위 테스트로 보장하지 않는다. 같은 이름의 모니터는 이름·순번으로 식별하므로 연결 구성이 바뀌면 선택 대상을 다시 확인해야 한다. 긴 본문은 자동 축소되므로 입력량과 영역 크기에 따라 가독성이 낮아질 수 있다. 저장 스냅샷은 자동 삭제하지 않아 저장 횟수에 따라 디스크 사용량이 증가한다.

서명·공증·배포와 Windows 실동작은 이 검토에서 수행하지 않았다. 테스트 파일은 OS 임시 디렉터리에 보존했다.

## 트레이 최소화 변경 검토 — 2026-11-20

macOS에서 변경 후 Rust 테스트 12개, 포맷 검사 및 `cargo clippy --manifest-path src-tauri/Cargo.toml --locked -- -D warnings`가 모두 종료 코드 0으로 통과했다. 추가 테스트는 트레이 템플릿 아이콘의 투명 배경과 십자가 픽셀을 확인한다.

- macOS 최소화 알림은 설정 창의 `NSWindow` 객체로 한정하여 setup의 주 스레드에서 한 번 등록한다. `NSNotificationCenter`가 알림 block을 유지하고 block은 앱 생명 동안 `AppHandle`을 보유한다. 앱 상태가 observer token을 다시 보유하지 않아 직접적인 순환 참조는 없다. 등록한 main 창은 닫기 요청을 가로채 보존한다.
- 닫기와 최소화는 두 플랫폼에서 설정 창만 숨긴다. Windows의 `Resized`·`is_minimized` 처리도 main 레이블 검사 안에 있어 오버레이 크기 변경이 설정 창을 숨기지 않는다.
- 트레이의 설정 열기는 최소화 해제 → 표시 → 포커스 순서로 복원한다. macOS는 숨길 때 Accessory, 복원할 때 Regular 활성화 정책을 적용한다.
- AppKit·Foundation·Objective-C block 의존성은 macOS 타깃에만 선언되어 있다. macOS는 단색 템플릿, Windows는 기본 컬러 앱 아이콘을 사용하여 어두운 작업 표시줄의 검정 단색 아이콘 문제를 피한다.

`cargo check --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-gnu --locked`도 시도했으나 Windows 리소스 도구 `x86_64-w64-mingw32-windres`가 없어 `tauri-winres` 단계에서 종료 코드 101로 중단됐다. Windows 앱 코드의 컴파일 완료나 실제 트레이 동작을 확인한 결과로 간주하지 않는다. 실제 메뉴 클릭·최소화·복원은 주 실행 검증 기록을 참고한다.

## 트레이 일시 중지 변경 검토 — 2026-11-20

최신 코드에서 `cargo test --manifest-path src-tauri/Cargo.toml --locked`의 13개 테스트, Rust 포맷 검사 및 Clippy 경고 검사가 모두 종료 코드 0으로 통과했다. 추가 테스트는 30분·1시간·2시간·4시간·8시간의 만료 직전과 정각, 기간 교체, 재개 및 일시 중지에 따른 자동 표시 판정을 확인한다.

- 종료 시각은 설정과 분리된 런타임 `SystemTime` 상태다. 일시 중지와 재개는 저장된 `enabled` 값을 변경하지 않으며 앱 재시작 시 초기화된다.
- 메뉴 콜백은 작업 스레드에서 처리하고, `Shared`와 메뉴 상태를 트레이 활성화 전에 등록한다. 표시 잠금 획득 후 자동 표시가 일시 중지를 다시 검사하므로 예약 판정과 메뉴 선택 사이의 경쟁을 막는다. 수동 미리보기는 일시 중지를 우회한다.
- 일시 중지 시 표시 세대를 갱신하고 보류 중인 모든 창의 요청과 종료 시한을 비운 뒤 오버레이를 숨긴다. 이전 준비·종료 콜백은 새 표시를 되살리거나 조기 종료할 수 없다.
- 메뉴 선택 순번으로 오래된 작업을 무시하여 작업 스레드 실행 순서가 바뀌어도 마지막 선택이 우선한다. 기존 예약 스레드가 자동 표시 사용 여부와 독립적으로 만료를 처리하고, 만료·재개 후 표시 간격을 다시 시작한다.

검토 범위에서 새 중대한 결함은 확인하지 못했다. 실제 메뉴 연속 조작·절전 복귀·30분 이상 대기 및 작업 스레드 경합을 단위 테스트로 재현하지 않았으며, 실제 실행 검증은 주 실행 기록과 구분한다. Windows 교차 검사 도구 부족은 앞 절과 동일하므로 반복 실행하지 않았다.
